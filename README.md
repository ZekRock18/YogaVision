# YogaVision

Real-Time Yoga Pose Classification and Feedback System.

A complete, runnable computer-vision application that classifies yoga poses from
a webcam, an uploaded image, or an uploaded video, and provides rule-based
posture feedback. Built as a working reproduction of the methodology in:

> Garg, S., Saxena, A., & Gupta, R. (2023). *Yoga pose classification: a CNN and
> MediaPipe inspired deep learning approach for real-world application.*
> Journal of Ambient Intelligence and Humanized Computing, 14(12), 16551–16562.
> Springer.
> DOI: [10.1007/s12652-022-03910-0](https://doi.org/10.1007/s12652-022-03910-0)

Original implementation: <https://github.com/shub-garg/Yoga-Pose-Classification-and-Skeletonization>

**Poses supported (5):** `downdog`, `goddess`, `plank`, `tree`, `warrior2`

---

## Pipeline

```
Camera / Image / Video
  -> OpenCV frame decode
  -> MediaPipe Pose landmark extraction (33 landmarks)
  -> Skeleton rendering on a black canvas   <- the paper's input representation
  -> resize to 75x75, scale to [0, 1]
  -> YogaConvo2d CNN  (custom 4-block ConvNet, ~21.6M params)
  -> softmax probabilities
  -> confidence threshold + temporal smoothing
  -> visualisation  ->  rule-based posture feedback  ->  session persistence
```

Runs entirely on CPU. No cloud inference, no paid API, no GPU required.

## Quick start (Windows, one-time setup)

Tested on Windows 11 with Python 3.11.0.

The two batch files in this folder do everything:

```
setup.bat    one-time: installs Python deps, creates .venv, runs the test suite
start.bat    every time: launches the app at http://localhost:8501
```

Run `setup.bat` once, then `start.bat` whenever you want to use the app.
The application opens at <http://localhost:8501>.

## Full pipeline setup (dataset + training)

If you also want to train the model yourself rather than reusing a
pretrained one:

```powershell
cd "E:\Computer Vision Project\YogaVision"

# 1. Create a virtual environment
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1

# 2. Upgrade pip and install dependencies
python -m pip install --upgrade pip
pip install -r requirements.txt

# 3. Install the package in editable mode (so `import yogavision` works)
pip install -e .

# 4. Download the dataset (Kaggle)
python scripts/download_assets.py

# 5. Skeletonize the dataset into the CNN input format
python scripts/prepare_dataset.py --raw data/raw/DATASET --out data/processed/yoga_poses_skeleton

# 6. Inspect what you downloaded
python scripts/inspect_dataset.py data/raw/DATASET/TRAIN --duplicates

# 7. Train the model (about 15 minutes on CPU for 40 epochs)
python scripts/train.py --config configs/train.yaml

# 8. Evaluate on the held-out test split
python scripts/evaluate.py --config configs/train.yaml

# 9. Run the application
streamlit run app.py
```

The app opens at <http://localhost:8501>.

If PowerShell blocks the activation script:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

## Results

A reproduction run completed on **2026-10-14** (CPU, Python 3.11.0,
TensorFlow 2.19.0, MediaPipe 0.10.21).

| Metric | Value | Provenance |
|---|---|---|
| Test accuracy | **0.6111** | reproduction run |
| Precision (macro) | 0.6233 | reproduction run |
| Recall (macro) | 0.5979 | reproduction run |
| F1 (macro) | 0.6037 | reproduction run |
| F1 (weighted) | 0.6105 | reproduction run |
| Mean inference latency | 67.3 ms | reproduction run |
| Approx FPS (CPU) | 14.9 | reproduction run |
| Test accuracy | 0.9709 | **original paper** |

Training: 1,080 skeletonized images, stratified split (755/216/109), 16 epochs
before early stopping, ~21.6M parameters, ~4 minutes on CPU.

### Why the reproduction does not match the paper

The paper's 97.09% is **not reproducible from its published notebook**, and the
gap is expected rather than a bug:

1. The notebook applies `validation_split=0.2` to **both** the train and test
   directories, and uses the test directory as its validation source. With 179
   duplicate image groups in this dataset, a random split leaks near-identical
   images across partitions and inflates the test number.
2. Train accuracy reached 0.836 while validation accuracy peaked at 0.657 — a
   large generalization gap for a 21.6M-parameter model on 755 images.
3. This project renders the full skeleton connection graph; the paper's script
   draws landmark dots only.
4. `mediapipe==0.10.21` produces different landmark coordinates than the
   2022-era version the authors used.

Full discussion in [`docs/methodology.md`](docs/methodology.md) §9 and
[`docs/research_notes.md`](docs/research_notes.md) §6.

## Troubleshooting

**`Model not available` in the UI** — `models/yoga_cnn.keras` does not exist.
Run `python scripts/train.py --config configs/train.yaml`.

**`Dataset directory not found`** — run `python scripts/download_assets.py`.

**Camera does not open** — Windows privacy settings:
*Settings > Privacy & Security > Camera*, and allow desktop apps. Also confirm
the camera index in the sidebar (the app probes indices 0–5).

**Video will not open** — codec unsupported by the bundled OpenCV. Convert with
FFmpeg: `ffmpeg -i input.mov -vcodec libx264 output.mp4`

**Slow training** — expected on CPU (~21 s/epoch with 1080 images). Reduce
`--epochs` or use `--limit` for a smoke test.

**Import errors** — run `pip install -e .` so `src/yogavision` is on the path,
or check that you are inside the virtual environment.
